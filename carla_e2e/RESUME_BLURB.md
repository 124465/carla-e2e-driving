# 简历项目描述 + 成果（可直接粘贴）

## 项目标题建议
**端到端自动驾驶模仿学习（行为克隆 + DAgger + 时序建模）** —— PyTorch / PyBullet / ROS2

## 一句话摘要
- 用 PyTorch 实现端到端驾驶策略（单目图像 → 转向/油门/刹车连续控制），在自建 PyBullet 仿真
  （双车道变曲率赛道 + 红绿灯 + 动态交通 + 跟车）上以行为克隆训练；独立定位并修复
  4 个"仿真状态未渲染导致观测不可推断"的问题，使 steer 预测相关系数从 **+0.03 提升到 +0.93**；
  实现 DAgger 缓解分布漂移，并封装为标准 ROS2 节点。

## 详细 bullet（按 STAR，挑 3-4 条）

1. **端到端策略与仿真环境**：设计轻量 CNN 从单目 160×80 图像直接回归 (steer, throttle, brake)；
   自建 PyBullet 场景含**双车道、变曲率赛道、红绿灯、动态交通与跟车**，专家为
   纯追踪 + 加加速度跟踪控制器（跟线、限速、红灯停车、跟车）。

2. **定位并修复"观测不可推断"问题（核心亮点）**：BC 长期学不会转向（MSE 恰等于
   "预测均值"基线、输出方差≈0），逐层排查排除架构/优化/数据量/多模态假设后，
   用**线性探针**（601 维降采样像素）定位到根因 —— **赛道曲率、车道线、红绿灯状态
   只存在于仿真器数学中，从未被渲染**；另发现相机完全水平（地面掠射角）、
   专家因油门下限而无法减速（红灯停车样本 0 条）。
   修复后 **steer 相关系数 +0.027 → +0.932**，MSE 0.0619 → 0.0065，三个通道全部学会。

3. **时序建模对比**：实现帧堆叠（`TemporalDrivingNet`）与 GRU（`GRUDrivingNet`）两种时序策略，
   从文件名解析 episode/步号构造时间窗（**窗口不跨 episode**）；统一训练入口保证可比。
   帧堆叠把 steer 相关系数从 **+0.697 提升到 +0.912**，MSE 降至 1/3.4。

4. **工程与性能**：将策略封装为标准 `ament_python` ROS2 包（订阅 `sensor_msgs/Image`、
   发布 `Float32MultiArray`）；实现 **GPU 驻留数据集**（uint8 常驻显存、按 batch 归一化，
   避免整份数据 float32 物化导致 OOM）与 **多进程并行采集**（实测 ~2x 加速，
   12000 帧 / 51s）。

## 技术栈
PyTorch · PyBullet · ROS2 Jazzy (rclpy/cv_bridge) · 行为克隆 / DAgger · 纯追踪 + Stanley 控制 ·
时序建模（帧堆叠 / GRU）· 多进程并行采集 · GPU 驻留数据管线

## 可量化成果
| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| steer 预测相关系数 | +0.027 | **+0.932** |
| steer MSE（基线 0.0415）| 0.0619（劣于基线）| **0.0065** |
| steer 输出 std（目标 0.216）| 0.0012（常数）| **0.2196** |
| 红灯停车步数 | 0 | 161 |
| 帧堆叠 steer 相关系数 | — | +0.912（单帧 +0.697）|

- 模型 ~3.2MB，轻量 CNN，适合边缘部署
- 默认 PyBullet 后端（安装包 98MB，对 SSD 零压力）；CARLA 为可选后端

## 面试可讲的三个"深度点"
1. **"MSE 低"不等于"学到了"**：必须与常数预测基线对比并检查输出方差。
   本项目两次栽在这个陷阱（steer std 退化、预测均值），因此把
   "是否超过均值基线"写成了硬性判定（`scripts/bench_models.py`）。
2. **BC 之前必须验证标签可推断性**：用线性探针 / 最近邻检查
   "观测是否包含标签信息"。这是本项目最省时间的做法 ——
   若先做这一步，能省掉大量在架构和超参上的无效尝试。
3. **仿真器的隐藏状态**：渲染缺失是模仿学习最隐蔽的失败模式，
   表现为"模型很努力但学不会"，而损失曲线看起来正常。
